# Мастер и лист: свободные статы, выбор черт, инвентарь-вкладка, кастомный КД, ручной ввод ресурсов, сворачиваемые секции (design)

Дата: 2026-08-19

## Цель

6 правок, уточнённых с пользователем:

1. Атрибуты без лимита очков.
2. Черты: свободный выбор нескольких (рандом — опция).
3. Инвентарь в отдельную вкладку с описанием, количеством и весом.
4. Кастомный КД брони.
5. Ручной ввод текущих HP/маны/выносливости.
6. Сворачиваемые секции интерфейса.

## A. Атрибуты без лимита (src/app.js, шаг 4 мастера)

- Убрать `pointsLeft()` и счётчик «Осталось очков: N» / подпись «27 очков поверх значения 8».
- Кнопки ± без гейта по бюджету: диапазон от 8 до потолка (`attrMax` — потолок расы, черта «Хрупкий» для живучести).
- Правило черты t12 «интеллект без 9» сохраняется.

## B. Черты — свободный выбор нескольких

**Данные:** `char.traitId: string|null` → `char.traits: string[]` (порядок = порядок выбора). Старые персонажи мигрируют при загрузке/рендере: если есть `traitId` и нет `traits` → `traits=[traitId]`. Поле `traitId` перестаёт использоваться (остаётся в данных для обратной совместимости чтения).

**CALC:**
- `traits(char, DATA)` → массив объектов-черт.
- `CALC.trait()` удаляется; все вызовы заменяются на итерацию по `traits()`:
  - `totalOS`: для каждой черты `osEvery3Levels` → `+floor(level/3)` (каждая черта даёт по одному за уровень), `osPerLevel` → суммируется.
  - `attrFinal`: `allAttrBonus` суммируется по чертам; `vitCap` → минимум из капов.
  - `mods`: `doubleWillMod` — если есть хоть одна такая черта.
  - Трекер: `rerollInit` (3 броска), `inspirationDaily` (кнопка «Новый день»), `intNot9`, t16/t10 правила — по наличию хотя бы одной соответствующей черты.
  - `levelUpModal`/заметки «Приспосабливаемый»/«Тупой» — по списку черт.

**Wizard шаг 3:** список всех черт (карточки-чекбоксы, выбор любого числа), кнопка «Кинуть d20» остаётся опцией (добавляет случайную черту в выбор, не заменяя), «Пропустить» остаётся. Экспорт/импорт — поле `traits` уходит в JSON как часть объекта.

## C. Инвентарь — вкладка

- Новая вкладка **«Инвентарь»** в таб-баре; с листа секция инвентаря убирается.
- Предмет: `{ name, desc, qty, weight }` — название, описание (textarea), количество (по умолчанию 1), вес (опционально, по умолчанию 0).
- Шапка вкладки: суммарный вес всех предметов.
- Добавление inline-формой; редактирование inline (поля в списке), удаление кнопкой.
- Данные: `char.inventory` — массив объектов; старые строковые предметы мигрируют в `{name: '<строка>', desc:'', qty:1, weight:0}`.

## D. Кастомный КД брони

- В выпадающем списке брони — пункт «Кастомная броня…». При выборе появляются поля «Название» и «КД».
- `char.armor = { id:'custom', label, ac }`. `CALC.ac()`: для `id='custom'` использует `armor.ac`, иначе — `DATA.armor[id].ac` (+ щит, + способности).

## E. Ручной ввод ресурсов

- На полосках Хиты/Запас сил/Мана текущее значение становится кликабельным → число → input (Enter/Blur подтверждает, Esc отменяет/сохраняет применимо), ограничение 0…max.
- New action `pool-set` (id: hp/stamina/mana). Кнопки ±/−/+ сохраняются.

## F. Сворачиваемые секции

- Обёртка `details`/`summary` (нативный, `open` по умолчанию) для всех секций: боевой трекер, снаряжение (броня/щит), оружие, дайсеры, атрибуты, инвентарь (в своей вкладке), каждая школа специализации на вкладке «Специализации», заметки.
- Реализация через хелпер `collapsible(title, contentEl, open=true)`.

## Совместимость

- Миграции выполняются идемпотентно при чтении персонажа; экспортированный JSON дополняется новыми полями.
- `verify`-батарея и харнессы обновляются под новые данные (харнесс-фикстуры получают `traits`/объектные предметы).
